# تبلیغ‌یار

مینی‌اپ سفارش تبلیغات کانال‌های ایتا. کاربر تعداد بازدید را انتخاب می‌کند، متن و لینک کانال و تصویر رسید را می‌فرستد؛ بررسی پرداخت و انتشار توسط مدیر به‌صورت دستی انجام می‌شود.

## امکانات
- بازه سفارش ۱٬۰۰۰ تا ۲۰۰٬۰۰۰ بازدید با گام ۱٬۰۰۰
- تعرفه اولیه ۹۰٬۰۰۰ تومان برای هر ۱۰٬۰۰۰ بازدید
- ثبت رسید تصویری در Supabase Storage خصوصی؛ دریافت رسید فقط برای مدیر احراز هویت‌شده
- ذخیره تعرفه زمان سفارش؛ تغییر تعرفه فقط روی سفارش‌های بعدی اثر دارد
- ورود مدیر، بررسی رسید، تغییر وضعیت و تنظیم تعرفه
- اعتبارسنجی امضای initData ایتا در سمت سرور

## اجرای محلی
نیازمند Node.js 20+، PostgreSQL و یک پروژه Supabase برای ذخیره خصوصی رسیدها:
1. دیتابیس را بسازید و `db/schema.sql` را اجرا کنید.
2. `.env.example` را به `.env` کپی کرده و مقادیر محلی را تنظیم کنید.
3. `npm install`، سپس `npm test` و در پایان `npm start` را اجرا کنید.
4. در محیط محلی می‌توان برای آزمایش رابط کاربری از `DEV_ALLOW_TEST_USER=true` استفاده کرد؛ این گزینه باید در تولید حتماً `false` باشد.

## استقرار Node.js مستقل (اختیاری)
این پروژه به‌صورت یک Node.js web service اجرا می‌شود:
- Runtime: Node.js 20 یا جدیدتر
- Root directory: `tabligh-yar` (اگر میزبان از ریشه پروژه پشتیبانی می‌کند)
- Build command: `npm install`
- Start command: `npm start`
- Health-check path: `/api/health`
- از PostgreSQL پروژه Supabase یا هر PostgreSQL سازگار استفاده کنید و `DATABASE_URL` را تنظیم کنید.
- فایل `db/schema.sql` را یک‌بار روی دیتابیس تازه اجرا کنید؛ برنامه به‌صورت خودکار جدول‌ها را ایجاد نمی‌کند.
- در Supabase یک Storage bucket با نام `receipts` و حالت **Private** بسازید. محدودیت فایل را ۵ مگابایت و MIME typeهای مجاز را `image/jpeg`, `image/png`, `image/webp` قرار دهید.
- متغیرهای `SUPABASE_URL` و `SUPABASE_SERVICE_ROLE_KEY` را فقط در تنظیمات محرمانهٔ هاست ثبت کنید. کلید `service_role` هرگز نباید در کد مرورگر یا GitHub قرار بگیرد.
- مقادیر محرمانه را فقط در پنل امن میزبان ثبت کنید: `SESSION_SECRET`، `EITAA_BOT_TOKEN`، `ADMIN_USERNAME` و `ADMIN_PASSWORD`.
- `SESSION_SECRET` باید حداقل ۳۲ نویسه تصادفی داشته باشد.
- رسیدها در Supabase Storage خصوصی ذخیره می‌شوند؛ فایل‌ها روی فایل‌سیستم موقت هاست قرار نمی‌گیرند. دیتابیس و Storage سهمیه و سیاست نگهداری مستقل دارند؛ پیش از استفاده، محدودیت‌ها و سیاست‌های پشتیبان‌گیری ارائه‌دهنده را بررسی کنید.
- پس از ساخته‌شدن دامنه نهایی HTTPS، مقدار `APP_ORIGIN` را با همان URL تنظیم و آن URL را در پنل رسمی برنامک ایتا ثبت کنید.

### راهنمای میزبانی رایگان
راهنمای اتصال Supabase و استقرار بک‌اند در [deploy/FREE-HOSTING.md](deploy/FREE-HOSTING.md) قرار دارد. طرح‌های رایگان ممکن است محدودیت خواب سرویس، سهمیه، توقف پروژه یا نبود بکاپ داشته باشند؛ رایگان بودن دائمی و بدون محدودیت تضمین نمی‌شود.

## امنیت و راه‌اندازی نهایی
- توکن ایتا، رمز مدیر، رشته اتصال دیتابیس و فایل `.env` را هرگز در GitHub یا گفتگو منتشر نکنید.
- در تولید از HTTPS استفاده کنید و `DEV_ALLOW_TEST_USER=false` باقی بماند.
- رسیدها فقط از مسیر احراز هویت‌شده مدیر قابل مشاهده‌اند.
- اتصال دیتابیس از تنظیم `sslmode` در `DATABASE_URL` پیروی می‌کند؛ برای اتصال خارجی PostgreSQL، TLS را طبق مستندات میزبان فعال کنید.
- نام فایل رسید در ستون `receipt_path` به‌عنوان کلید شیء Storage ذخیره می‌شود؛ برای پروژه‌های قدیمی که رسیدها روی دیسک محلی بوده‌اند، مهاجرت فایل‌های قبلی جداگانه لازم است.
- پس از استقرار، `/api/health`، ورود واقعی ایتا، ثبت سفارش آزمایشی، مشاهده رسید از حساب مدیر و ماندگاری رسید پس از redeploy را آزمایش کنید.
- حساب مدیر فقط در اولین ایجاد ساخته می‌شود؛ تغییر `ADMIN_PASSWORD` در متغیرهای محیطی، رمز هش‌شده موجود را عوض نمی‌کند. برای تغییر رمزِ حساب موجود، باید هش جدید در دیتابیس جایگزین شود.
- ثبت برنامک در ایتایار و احراز هویت توسعه‌دهنده باید از مسیر رسمی انجام شود؛ هیچ مرحله احراز هویتی را دور نزنید.

## وضعیت
این مخزن سورس‌کد و پیکربندی استقرار است، نه سرویس آنلاین. هنوز هاست، دیتابیس واقعی، توکن واقعی ایتا و دامنه نهایی به پروژه متصل نشده‌اند؛ بنابراین ورود و سفارش واقعی در محیط ایتا تأیید نشده است.
