# تبلیغ‌یار

مینی‌اپ سفارش تبلیغات کانال‌های ایتا. کاربر تعداد بازدید را انتخاب می‌کند، متن و لینک کانال و تصویر رسید را می‌فرستد؛ بررسی پرداخت و انتشار توسط مدیر به‌صورت دستی انجام می‌شود.

## امکانات
- بازه سفارش ۱٬۰۰۰ تا ۲۰۰٬۰۰۰ بازدید با گام ۱٬۰۰۰
- تعرفه اولیه ۹۰٬۰۰۰ تومان برای هر ۱۰٬۰۰۰ بازدید
- ثبت رسید در Supabase Storage خصوصی؛ دریافت رسید فقط برای مدیر احراز هویت‌شده
- ذخیره تعرفه زمان سفارش؛ تغییر تعرفه فقط روی سفارش‌های بعدی اثر دارد
- ورود مدیر، بررسی رسید، تغییر وضعیت، ثبت بازدید نهایی و تنظیم تعرفه
- اعتبارسنجی امضای initData ایتا در سمت سرور

## نسخه آنلاین

Edge Function نسخه ۲ با وضعیت ACTIVE روی پروژه Supabase مستقر شده است.

- **آدرس مینی‌اپ:** https://nvegaokijnrknjwctkbt.supabase.co/functions/v1/tabligh-yar
- **آدرس سلامت:** https://nvegaokijnrknjwctkbt.supabase.co/functions/v1/tabligh-yar/api/health
- **داشبورد پروژه:** https://supabase.com/dashboard/project/nvegaokijnrknjwctkbt
- **تنظیم secrets:** https://supabase.com/dashboard/project/nvegaokijnrknjwctkbt/functions/secrets

برای فعال‌شدن ورود واقعی و پنل مدیریت، این سه secret باید در داشبورد Supabase ثبت شوند:
- `EITAA_BOT_TOKEN`
- `ADMIN_USERNAME`
- `ADMIN_PASSWORD`

کلیدهای Supabase در محیط Edge Function به‌صورت خودکار موجودند. هیچ secret را در GitHub یا گفتگو قرار ندهید. پس از ثبت secrets نیازی به deploy مجدد تابع نیست. ثبت و تأیید Mini App در پنل رسمی ایتا نیز باید انجام شود.

## ساختار کد Edge Function

کد تابع در `supabase/functions/tabligh-yar/` و تنظیمات CLI در `supabase/config.toml` نگهداری می‌شود. تابع صفحه HTML، فایل‌های CSS/JS و API را از یک مبدأ ارائه می‌کند. `verify_jwt=false` است چون خود تابع اعتبارسنجی امضای ایتا، نشست مدیر و CSRF را انجام می‌دهد؛ دسترسی مدیریتی بدون نشست معتبر پذیرفته نمی‌شود.

## دیتابیس و Storage

- فایل ساختار دیتابیس: `db/schema.sql`
- جدول‌ها: `app_settings`, `admins`, `ad_orders`, `order_events`
- RLS برای هر چهار جدول فعال است و دسترسی عمومی تعریف نشده است.
- bucket با نام `receipts` خصوصی است؛ حداکثر ۵ مگابایت و فقط JPEG، PNG و WebP.
- رسیدها با نام تصادفی ذخیره می‌شوند و فقط مدیر احراز هویت‌شده می‌تواند آن‌ها را از API دریافت کند.

## اجرای نسخه Node.js به‌صورت محلی

نیازمند Node.js 20+ و PostgreSQL:
1. فایل `db/schema.sql` را روی دیتابیس اجرا کنید.
2. `.env.example` را به `.env` کپی و مقادیر محلی را تنظیم کنید.
3. `npm install`، سپس `npm test` و `npm start`.
4. فقط برای آزمایش محلی می‌توان `DEV_ALLOW_TEST_USER=true` گذاشت؛ در محیط واقعی باید `false` باشد.

## امنیت و محدودیت‌ها

- توکن ایتا، رمز مدیر، رشته اتصال دیتابیس و کلیدهای Supabase را هرگز در GitHub یا گفتگو منتشر نکنید.
- رسیدها عمومی نیستند و لینک مستقیم عمومی برای آن‌ها ساخته نمی‌شود.
- تغییر `ADMIN_PASSWORD` پس از ساخته‌شدن رکورد مدیر، هش موجود را خودکار عوض نمی‌کند؛ برای تغییر رمز مدیر باید رکورد هش‌شده به‌روزرسانی شود.
- پلن رایگان Supabase سهمیه دارد و ممکن است پروژه کم‌فعالیت را متوقف کند؛ رایگان بودن دائمی و بدون محدودیت تضمین نمی‌شود.
- قبل از استفاده واقعی، سلامت API، ورود واقعی ایتا، ثبت سفارش آزمایشی، مشاهده رسید از پنل مدیر و تغییر وضعیت را آزمایش کنید.
