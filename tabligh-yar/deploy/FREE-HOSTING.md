# راهنمای استقرار با هزینه صفر (در محدوده سهمیه رایگان)

این چینش برای کاهش هزینه طراحی شده است؛ هیچ ارائه‌دهنده‌ای رایگان بودن دائمی، بدون محدودیت یا بدون نیاز به تأیید شرایط حساب را تضمین نمی‌کند. پیش از ثبت‌نام، قیمت و شرایط فعلی را بررسی کنید و هیچ طرح پولی یا افزودن روش پرداخت را فعال نکنید.

## معماری پیشنهادی

- **Backend:** یک میزبان Node.js با پلن رایگان که از اتصال به PostgreSQL و متغیرهای محیطی پشتیبانی کند.
- **Database:** پروژه Supabase PostgreSQL در پلن Free یا هر PostgreSQL رایگان سازگار.
- **Receipt storage:** یک bucket خصوصی در Supabase Storage؛ بک‌اند با کلید محرمانه `service_role` فایل را ذخیره و فقط پس از احراز هویت مدیر آن را دریافت می‌کند.

## ۱) ساخت پروژه Supabase

1. یک پروژه جدید در Supabase ایجاد کنید و در صورت امکان نزدیک‌ترین Region به میزبان بک‌اند را انتخاب کنید.
2. در SQL Editor محتوای `db/schema.sql` را اجرا کنید.
3. از Storage یک bucket به نام `receipts` بسازید و حتماً آن را **Private** نگه دارید.
4. سقف اندازه فایل را ۵ مگابایت قرار دهید.
5. در صورت امکان MIME typeهای مجاز را به `image/jpeg`, `image/png`, `image/webp` محدود کنید.
6. از Project Settings مقادیر Project URL و کلید محرمانه `service_role` را بردارید. کلید را فقط در Environment هاست وارد کنید؛ آن را در مرورگر، کد عمومی، GitHub یا گفتگو قرار ندهید.

## ۲) استقرار بک‌اند

در میزبان سازگار Node.js:
- Repository: `2013shayan1392-commits/-Chatgpt`
- Branch: `tabligh-yar`
- Root directory: `tabligh-yar`
- Build command: `npm install`
- Start command: `npm start`
- Health check: `/api/health`
- Node.js: نسخه ۲۰ یا جدیدتر

مقادیر محیطی را در پنل میزبان وارد کنید:
- `NODE_ENV=production`
- `DATABASE_URL` = رشته اتصال PostgreSQL از Supabase
- `SESSION_SECRET` = مقدار تصادفی حداقل ۳۲ نویسه
- `EITAA_BOT_TOKEN` = توکن رسمی ایتا
- `ADMIN_USERNAME` و `ADMIN_PASSWORD` = اطلاعات ورود مدیر
- `SUPABASE_URL` = Project URL
- `SUPABASE_SERVICE_ROLE_KEY` = کلید محرمانه سمت سرور
- `SUPABASE_STORAGE_BUCKET=receipts`
- `DEV_ALLOW_TEST_USER=false`
- `APP_ORIGIN` = آدرس HTTPS نهایی Mini App

## ۳) کنترل‌های امنیتی و آزمون

1. مطمئن شوید bucket خصوصی است و کلید service_role فقط در محیط سرور وجود دارد.
2. مسیر `/api/health` باید پاسخ سالم بدهد.
3. ورود واقعی ایتا را در محیط رسمی آزمایش کنید.
4. یک سفارش آزمایشی با رسید معتبر ثبت کنید.
5. با حساب مدیر رسید را از مسیر پنل دریافت کنید و مطمئن شوید کاربر عادی نمی‌تواند آن را دریافت کند.
6. یک redeploy انجام دهید و دوباره رسید را بررسی کنید.
7. برای داده‌های مهم، روش پشتیبان‌گیری مستقل در نظر بگیرید؛ پلن رایگان ممکن است بکاپ خودکار نداشته باشد.

## محدودیت‌های مهم

- میزبان رایگان ممکن است در حالت بیکاری بخوابد، محدودیت زمان اجرا یا ترافیک داشته باشد یا در آینده شرایط پلن خود را تغییر دهد.
- دیتابیس یا Storage ممکن است سهمیه، محدودیت حجم یا سیاست توقف/حذف پروژه داشته باشد.
- این معماری برای شروع آزمایشی مناسب است، اما تا وقتی محدودیت‌ها و پشتیبان‌گیری بررسی نشده‌اند، نباید آن را تضمین ماندگاری بلندمدت داده‌ها دانست.
- هیچ پرداخت، ارتقای پولی یا ثبت کارت بانکی برای این راهنما لازم نیست؛ اگر ارائه‌دهنده چنین چیزی را اجباری کرد، از آن مسیر استفاده نکنید.
- مراحل ثبت و تأیید برنامک ایتا باید از مسیر رسمی و مطابق شرایط سنی و قوانین حساب انجام شود.
