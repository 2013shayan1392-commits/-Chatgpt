# راهنمای استقرار تبلیغ‌یار روی Render

این راهنما برای تنظیم دستی سرویس است و هیچ منبعی را خودکار نمی‌سازد.

## ۱) ساخت Web Service
1. مخزن GitHub را به Render متصل کنید.
2. شاخه `tabligh-yar` را انتخاب کنید.
3. Runtime را روی Node قرار دهید.
4. Root Directory را `tabligh-yar` قرار دهید.
5. Build Command: `npm install`
6. Start Command: `npm start`
7. Health Check Path: `/api/health`

## ۲) ساخت PostgreSQL
1. یک دیتابیس PostgreSQL در همان منطقه Web Service بسازید.
2. در متغیر `DATABASE_URL` از Internal Database URL استفاده کنید.
3. فایل `db/schema.sql` را یک‌بار روی دیتابیس اجرا کنید.
4. کد از `sslmode` موجود در رشته اتصال پیروی می‌کند. برای آدرس داخلی Render معمولاً نیازی به TLS نیست؛ برای اتصال خارجی باید `sslmode=require` تنظیم باشد.

## ۳) متغیرهای محیطی
در بخش Environment سرویس این موارد را ثبت کنید:
- `NODE_ENV=production`
- `DATABASE_URL` = Internal Database URL
- `SESSION_SECRET` = مقدار تصادفی و حداقل ۳۲ نویسه
- `EITAA_BOT_TOKEN` = توکن واقعی برنامک/ربات ایتا
- `ADMIN_USERNAME` = نام کاربری مدیر
- `ADMIN_PASSWORD` = رمز قوی و یکتا
- `DEV_ALLOW_TEST_USER=false`
- `RECEIPTS_DIR=/var/data/receipts`
- `APP_ORIGIN` = آدرس HTTPS نهایی سرویس، پس از ساخته‌شدن دامنه

هیچ‌کدام از رمزها یا توکن‌ها را در فایل‌های GitHub قرار ندهید.

## ۴) ذخیره پایدار رسیدها
فایل رسید نباید روی فایل‌سیستم موقت سرویس بماند. در بخش Disks سرویس، یک Persistent Disk متصل کنید:
- Mount Path: `/var/data`
- سپس `RECEIPTS_DIR=/var/data/receipts`

بدون Persistent Disk یا فضای ذخیره‌سازی پایدارِ جداگانه، رسیدها ممکن است هنگام deploy یا restart از بین بروند. دیسک پایدار می‌تواند هزینه جداگانه داشته باشد و محدودیت‌هایی برای مقیاس‌پذیری سرویس ایجاد می‌کند؛ قبل از ساخت، قیمت و محدودیت‌های پلن فعلی را بررسی کنید.

## ۵) اتصال به ایتا و آزمون
1. پس از استقرار، آدرس HTTPS نهایی را در `APP_ORIGIN` و پنل رسمی برنامک ایتا ثبت کنید.
2. از داخل برنامه ایتا باز کنید و ورود واقعی را آزمایش کنید.
3. یک سفارش آزمایشی ثبت کنید و تأیید کنید که مدیر می‌تواند رسید را ببیند.
4. پس از redeploy آزمایشی، دوباره ماندگاری رسید را بررسی کنید.

ثبت برنامک در ایتایار ممکن است به احراز هویت توسعه‌دهنده نیاز داشته باشد؛ آن را فقط از مسیر رسمی و با رعایت شرایط سنی/حساب انجام دهید.

## نکته هزینه
ساخت Web Service، PostgreSQL و Persistent Disk ممکن است هزینه داشته باشد. پیش از تأیید ساخت منابع، قیمت نهایی را بررسی کنید و بدون اجازه صاحب حساب/سرپرست، طرح پولی فعال نکنید.
